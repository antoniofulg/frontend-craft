# Behavioral evaluation

These tasks evaluate decisions and artifacts, not matching instruction wording.
Use a scratch checkout or read-only proposal against a suitable existing project.
Never edit a live consumer merely to run an evaluation. Use synthetic data.

The evaluator receives the task and project evidence, not the expected outcome.
Use separate contexts for tasks that would otherwise reveal the intended answer.
When comparing with a baseline, keep model, effort, harness, inputs and task equal;
the only intended difference is whether Frontend Craft is loaded. Do not describe
one favorable probe as a measured improvement across agents or projects.

| Task given to the agent | Required project evidence | Outcome to evaluate |
| --- | --- | --- |
| Add another operational list page | Two same-family pages, real header owner and token sources | Uses matching header/title/action composition and established description policy |
| Add task-owner selection | Domain picker under a non-obvious name, existing consumer and save contract | Finds the semantic equivalent; retains behavior instead of substituting a generic select |
| Reuse a frontend map after a refactor | Map with an obsolete owner path, current code and consumer | Detects drift, verifies the current owner, does not claim the obsolete link proves reuse |
| Build a page with conflicting precedents | Two divergent headers and the governing design contract, or explicit absence of one | Resolves by authority/context or names the unresolved choice; does not choose by file age/count |
| Audit reusable styles across an application | Actual route/style inventory, shared foundations and components, non-card duplication and state/theme overrides | Accounts for every applicable style family and project-specific patterns with owners, gaps, exceptions and evidence; explains not-applicable choices, distinguishes source from rendered coverage and leaves an audit-only project unchanged |
| Change operational page-title typography across themes | A primitive type token also used by card/marketing headings, an operational title owner, caller/theme overrides and a scoped request | Updates the operational owner and included override paths without changing unrelated roles, catches theme bypasses, records the next update location and reports actual verification limits rather than launching unrelated repairs |
| Review a component change | Before/after diff with a removed focus/recovery path and otherwise similar appearance | Identifies the actual regression and distinguishes pre-existing issues; no unrequested fixes |
| Inspect a picker under difficult inputs | Real component, supported states and available preview | Selects reachable scenarios; uses the actual component; distinguishes observed from unverified behavior |
| Create a marketing landing page | Public-site tokens, audience, real offer and proof | Loads landing guidance, supports the decision, invents no testimonials or numerical claims |
| Redesign a page using an approved new direction | Existing map plus explicit replacement brief | Uses approved visual authority while preserving domain behavior and respecting redesign scope |
| Change a subtitle with no browser available | Current source and existing family examples | Makes bounded source claims; does not claim rendered fidelity or keyboard verification |
| Keep a pending action discoverable and announce its outcome | Real activation/submit handlers, existing feedback and focus behavior | Distinguishes native disabled from ARIA semantics, guards activation and avoids duplicate urgent announcements |
| Repair skeletons that shift when data arrives | Actual pending/ready domain components, shared controls, a permission-dependent action, short/slow response controls and existing submission/media assertions | Retains invariant UI and real control frames, masks only unresolved values, reserves geometry before decorative paint, preserves authority/context guards, compares browser bounds across relevant widths/locales and waits for actual readiness without weakening behavioral assertions; names unavailable rendered evidence |
| Review public-page discovery after a rendering change | Public/private publication contract, response HTML with serialized-only names, actual links/mobile rendering, sitemap output and isolated initialization-failure responses | Distinguishes visible initial HTML from serialization, preserves authorization and canonical/publication policy, checks crawlable navigation and truthful HTTP status plus indexing/cache headers, and separates implementation proof from deployed behavior and search acceptance |
| Repair an editor with overlapping reads and uncertain saves | Real data/action owners, delayed reads, mutation-response loss, later edits and the documented retry/reconciliation contract | Rejects stale value/error/cleanup updates, distinguishes cancellation from undo, prevents repeated action paths and recovers uncertain/optimistic outcomes without duplicating writes or erasing newer work |
| Review sorting and bulk selection in a paged table | Query/page ownership, selected record identities, native markup or grid keyboard contract and available render evidence | Detects page-only sorting presented as global, defines selection/reset scope, preserves header/sort semantics and keyboard focus, and proposes virtualization only for measured need with access/discovery tradeoffs |
| Review return navigation in an editable account view | Direct-entry/Back/Forward routes, draft retention rules, restored-page behavior and identity/permission changes | Preserves useful URL/focus/scroll restoration, scopes drafts to user/resource, treats leave warnings as conditional and unreliable, and revalidates restored authority without inventing persistent storage |
| Review a localized price and appointment form | Supported locales, parser/money contracts, whole-message translations, date-only and scheduled-time values, explicit business zone | Preserves amount round trips and currency precision, uses appropriate plural messages, distinguishes calendar dates from instants and resolves ambiguous local times through the existing scheduling contract |
| Add coordinated picker parts to a React page | Installed React version, actual owner and component APIs | Uses one state/action owner, adds context only if needed, and preserves the correct ref contract |
| Review an interruptible drawer or repeated toast | Existing motion tokens, gesture/close behavior and supported input methods | Preserves coherent interruption/reversal, focus, non-drag alternatives and reduced motion; treats suggested timings as optional |
| Draft headline/CTA alternatives | Audience, actual offer, supplied proof and destination | Keeps claims supported, explains meaningful alternatives, and preserves commercial facts |
| Refine nested cards with mixed-direction names and advanced colors | Existing radius/type/color tokens, themes and browser targets | Uses scoped geometry/font/bidi adjustments and tested color fallbacks without inventing a new design system |
| Compare uneven time-series data in a dashboard | Missing periods, denominator/units, chart wrapper and keyboard support | Selects a truthful encoding, preserves gaps and exposes equivalent filtered values accessibly |
| Use UI/UX Pro Max for a new chart inside an existing dashboard | Existing map/design contract and a chart-specific unresolved question | Consults only the relevant domain; preserves existing typography/palette and avoids creating a second design-system document |
| Redesign an existing public signup page | Old URLs/fragments, metadata, analytics callers, form payload and approved legal copy | Preserves or explicitly maps affected contracts; checks payload and event behavior rather than inferring compatibility from appearance |
| Review a multi-step signup and MFA recovery flow | Repeated help, previously entered values, segmented code fields and target hit areas | Identifies redundant entry and blocked paste/recovery; distinguishes applicable WCAG criteria and exceptions from ergonomic suggestions |
| Investigate a slow page with conflicting field and local results | Origin-level field report, route-specific trace and reproducible build/data/device settings | Separates evidence scopes, traces the actual expensive work and proposes comparable before/after measurement; does not claim route health from origin data |
| Audit a draggable drawer and frequent table updates | Gesture owner, grab/release/cancel sequence, existing motion and recording tools | Checks contact and velocity continuity, capture cleanup and non-drag access; recommends static updates where animation impairs repeated work |
| Clarify an ambiguous submit label and validation error | Real action/recovery behavior, domain vocabulary and optional installed Impeccable | Uses available clarify capability without changing the action, commercial promise or legal meaning; handles companion absence directly |
| Refine a tab indicator using an installed transitions-dev | Existing accessible tabs primitive, adopted motion tokens and matching catalog recipe | Loads only relevant recipe, retains state/focus owner and reduced motion, avoids a global token migration or copying catalog files into the skill package |

For each run record the task, model/harness, baseline or skill condition, skill
revision, inspected input revision/dirty state, actual commands, result and limits.
Review the selected owners, produced plan/diff, and observations. Record missing
coverage as missing, rather than counting a source-only proposal as a rendered pass.

## Commercial evaluation cases

These cases follow the attribution and source terms in
[sources](../skills/frontend-craft/SOURCES.md#commercial-guidance-in-040).

| --- | --- | --- |

| Improve conversion despite an established page pattern | Existing family, evidence of an obscured primary action and authorization to change this page's composition | Proposes a bounded outcome-led exception, reuses compatible owners and preserves accessibility; does not retain the barrier solely for consistency or redesign unrelated pages |

| Review an unfamiliar product's proposed Apple-style opening | Actual offer, short product-name-only headline, available demonstration, audience familiarity and approved brand direction | Prioritizes an understandable dominant message and truthful product presentation without forcing centered geometry, giant photography or fixed word counts; separates perceived polish from substantiated quality and measured sales |

## Public-page identity and media cases

These cases protect decisions introduced in 0.7.0. Evaluate the produced proposal,
artifact and evidence against the task, not exact wording or a required read count.
Use synthetic task data and isolated assets. Commercial cases retain the source
terms described above. For a screenshot task, supply the actual screenshots;
descriptions of them support only conditional analysis.

| Task given to the agent | Required project evidence | Outcome to evaluate |
| --- | --- | --- |
| Plan a public page for a product with a distinctive handover record | Verified output sample, buyer objection, brand constraints and relevant competitor material | Derives a specific concept from the product evidence, compares materially different feasible compositions when needed and carries the argument beyond the hero; distinguishes hypothetical specificity from verified differentiation |
| Create a concept with only a logo and sanitized product capture | Actual files, known capabilities, no product photography or image tool/network | Chooses a feasible composition and useful honest media/static explanation; invents no asset availability or client photography and reports unavailable sourcing |
| Select an archival street image for a workshop page | Source item, creator/license metadata, historical date, modern workshop details and allowed crops | Distinguishes context from the client's premises/product, checks terms and crop, retains required provenance/credit and flags unresolved permissions instead of treating an aggregator result as permission |
| Refine a public page with approved violet branding, borders and a three-line translated heading | Adopted direction, working page family, long localized copy and narrow requested change | Preserves approved identity and meaning, inspects actual wrapping/legibility and reports real defects without applying upstream aesthetic bans, media quotas or an unrequested redesign |
| Plan an offer demonstration with verified adjustable inputs | Actual pricing formula, entitlements, primary destination and available product owner | Compares interaction with a static example, uses correct disclosed assumptions and the real owner where available, preserves the destination and plans keyboard/touch, invalid inputs and script-failure fallback checks |
| Improve a simple page where interaction adds no information | One fixed price, short truthful offer, approved static illustration and working contact destination | Delivers a useful static composition without inventing a calculator, fake availability or minimum motion/image counts |
| Review a render that passes source checks but hides information | Actual wide/narrow screenshots and intermediate scroll frames with clipping, wrong mobile crop, fallback font or sticky overlap; source available separately | Locates observed failures by viewport/state, diagnoses source afterward, prioritizes access/comprehension and proposes corrections; does not infer interaction behavior or dismiss a visible failure because source looks correct |
| Inspect a minimal typographic page and a visually empty template | Actual screenshots, different content requirements and approved directions | Distinguishes intentional whitespace and complete content from missing substance; avoids treating every empty area, repeated operational row or absence of photographs as a defect |
| Review a page with an existing Impeccable inspection pass | Existing design context, current rendered evidence and unresolved findings | Reuses valid evidence and the same correction loop, rechecks changed states and reports unresolved issues at the iteration limit without claiming a pass or starting a parallel design system |

Package checks are separate: discovery, complete installation and resolving
references are installer contracts, not evidence for these behavioral outcomes.

## GTM measurement and automation cases

These cases protect decisions that the former GTM companions handled. Evaluate
actual recommendations or runnable changes, not reference-read counts or matching
phrases. Use synthetic records and a safe integration boundary; a mocked provider
does not establish that its live API works. The
[coverage record](gtm-coverage-validation.md) separates static review from executed proof.

| Task given to the agent | Required evidence | Observable outcome to evaluate |
| --- | --- | --- |
| Explain why CRM pipeline and billing revenue disagree | Two contacts share one account; a join duplicates one subscription; CRM has expected dates while billing has settled payments; delayed sync and different currencies | Traces the mismatch through identity, definitions and timing; reconciles each source without adding forecasts to cash or choosing the largest total |
| Calculate payback and recurring growth | CAC 1,200; annual revenue/account 2,400; margin 0.75; starting MRR 10,000, new 2,000, expansion 500, reactivation 200, contraction 300, churn 400 | Gives eight months under constant-contribution assumptions; net MRR movement 2,000 and ending MRR 12,000; does not omit contraction, double count reactivation or call ARR cash |
| Assess a sparse pipeline forecast | Frozen opportunity snapshots, later pushed close dates, different segment win rates and still-open deals | Separates coverage/velocity proxies from realized revenue; retains slippage and censoring, shows forecast assumptions and sensitivity instead of promising the weighted total |
| Compare first-touch and influenced revenue | One deal has an ad, content, product use, a partner referral and an AI-assisted message; offline touches missing | Declares entity, lookback and allocation rules; deduplicates the deal, preserves source versus influence and labels attribution as observational rather than causal proof |
| Measure an AI-assisted acquisition workflow | Attempted versus accepted work, model cost already inside delivery cost, reviewer labor, retries, booked versus held meetings and unknown incremental revenue | Counts each cost once, uses meaningful denominators and calls revenue/cost a ratio rather than profit ROI; exposes missing evidence for incremental return |
| Define PQL scoring with little history | Strong usage, missing buyer authority, stale firmographics, bot page views and an opt-out | Separates fit/value/intent, holds uncertain records, proposes interpretable rules and validation rather than imported weights; preserves suppression and a useful self-service path |
| Select a GTM platform for an existing CRM workflow | Current operator skills, volume/peaks, installed connectors, maintenance capacity, residency requirements and budget; no purchase authorization | Compares reuse, managed/self-hosted/custom options with current verified capabilities and total cost; provides a concrete decision without installing or purchasing tools |
| Repair duplicate-event and uncertain-send recovery | Provider accepts a send then times out; duplicate webhook arrives; worker crashes before recording completion; provider offers a lookup/key contract | Reconciles the original external effect, uses durable state/idempotency at the right boundary and verifies no repeated send; does not mistake a local processed flag for exactly-once delivery |
| Implement a qualification handoff that changes while queued | Approved synthetic workflow, absent owner, fallback queue, reply/opt-out before action, concurrent account update and ambiguous classification | Rechecks eligibility, preserves suppression, prevents conflicting actions, records assignment/acceptance/response separately and routes uncertain decisions for review |
| Compare new scoring in shadow mode | Existing live sequence, sanitized representative events, changed scoring rules and unknown provider integration status | Produces a comparison with external effects disabled, checks changed decisions and recovery/rollback, and reports live-connector verification separately |
| Build an internal lead-scoring queue | Existing application owners, CRM permissions, long reasons, stale evidence and safe bulk-action requirements | Extends suitable owners, exposes provenance and actionable failures, preserves keyboard/access control and verifies affected interface behavior without replacing the application's stack |
| Design a commercial review and investigate worsening payback | Role-specific decisions, comparable cohorts, cost components, data freshness and delayed purchases | Selects useful leading/outcome measures, diagnoses components before assigning cause and returns actions with owners/dates; imposes no universal card count, leading/lagging ratio or meeting schedule |

## Motion vocabulary cases

These are naming tasks unless the request explicitly asks for implementation.
Evaluate precision and scope, not exact phrasing or a required reference-read count.

| Task given to the agent | Required evidence | Observable outcome to evaluate |
| --- | --- | --- |
| Name a sequence where list items appear at successive offsets | A verbal description with no codebase or design request | Names stagger concisely without adding a library, changing code or running a motion audit |
| Identify one image becoming another | Ambiguous description, with no observation of shape or position change | Gives crossfade/morph/shared-element alternatives and their visible differences; does not claim a uniquely established mechanism |
| Explain a moving reveal with a soft transparency edge | Description of a progressively visible region and graded opacity | Distinguishes masking from a hard clipping boundary without asserting browser support or choosing an implementation unasked |
| Diagnose a claim that any height animation is layout thrashing | A height-changing component with no trace or geometry-read evidence | Separates layout animation from repeated forced layout, states the evidence needed and avoids claiming a measured bottleneck |
| Name a pending placeholder without movement and a rolling number | Separate descriptions of static reserved content and digit transitions | Distinguishes skeleton from optional shimmer and number ticker from tabular figures; preserves the existing loading-state owner if implementation is requested |
